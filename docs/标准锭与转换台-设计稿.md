### 0.1 已定死的规则（原样落实）

1. **标准锭是独立物品**：不能融化 / 不能重冶炼 / 不能当普通锭用；**机器配方按物品名（物品 id）匹配拒收**——逐条测试点见 §5.8。
2. **转换台**：电 **64 FE/t**，**5 秒 = 100 刻 / 件** ⇒ **6400 FE / 件**；**失败销毁输入**（照扣电）；**概率下限 0%**（公式 clamp 的下界；实际不可达 —— 见本节第 5 条）。
3. **概率公式**（基准固定 **70%**）：
   P = 0.70 × Π(1 − f_非有害杂质_i) − Σ f_有害杂质_i，clamp 到 [0, 1]。
   - 非有害杂质 = 一份「纯稀释剂」白名单（没有特殊效果、只是降低纯度，例如钢里的锌）；
   - 其它一切都算有害杂质（加算扣百分点），包括硫 / 磷 / 渣 / 氧化物 / 其他金属；
   - 用户例子：78% 铁 + 2% 碳 + 10% 锌 + 10% 硫 → 标准钢 98/2：70% × 0.90 = 63% → −10 = **53%**（§3.4 样例 S3 自检一致）。
4. **入料门槛**：合金配方内**金属总含量 > 70%**（不合格：停机、显示「不合格」、**不空烧电**、不销毁输入）。
   本稿按用户的族模型把它细化为**每锭自己的入料窗口**（§3.3），每个窗口的必要条件都保持「该锭合金金属集合合计 > 70%」（全部窗口的 A 下限都 ≥ 71%，见表 1-B）。
   **口径 A（「该合金配方内的金属合计 > 70%」）已由用户确认定稿**；据此 **P ∈ [41.00%, 70.00%]**，**P = 0 不可达** ⇒ 仍不需要「P=0 拒收」（§3.3）。
5. **P 的下限与安全行为**（用户修正 1，覆盖初稿）：在窗口模型下 **P 在数学上不可能为 0** —— 窗口要求合金金属
   合计 ≥ A_min ≥ 71%，余下 ≤ 29% 全给有害项时 P = 0.70 − 0.29 = **41.00%**（有稀释剂时更高）。
   因此**不设「P=0 拒收」安全阀**；界面只做「两位小数 + 拆解显示」，玩家自行判断（用户口径：玩家也不是傻子）。
6. **族模型**（用户修正 2）：**一级 = 族，二级 = 具体标准锭**。铜基/铝基**不是一种合金而是一簇**
   （黄铜 Cu-Zn / 青铜 Cu-Sn / 白铜 Cu-Ni；硬铝 Al-Cu-Mg / 铝硅 / 铝镁），每种标准锭有**自己的固定成分、自己的窗口、自己的用途**；
   窗口必须严到能区分同族成员（喂 Cu+Zn 不该出青铜）。
7. **进阶机是新方块**（不是就地改造），**从头用特殊合金 / 标准锭合成**；普通机器配方**只用原版可得材料**
   （既有约定，docs/配方与任务书.md:214「全原版材料」）。
8. **改件**：通用改件只出通用词缀、专有改件只出专有词缀；**同类词缀相乘**；**破坏进阶机时改件原地掉落**；
   进阶机**必须装满它需要的改件**才能运行；以后会有「增加成功概率」的改件（转换台用）。
9. **进阶转换台改件**（用户点名）：**电动机改件 / 压制滚轮改件 / 锻造锤头改件 / 批量转化改件**——放置后增加可用输入 / 输出槽位；
   第 5 个是「增概率改件」（加算概率、不增槽）。
10. **用途映射（本轮用户决定，硬约束）**：**标准锭只用于合成机器本体（方块）**；
    **改件（模块）一律用「未标准化的普通金属」制造**（改件吃**提炼锭**，不吃标准锭）。

## 一、数据与口径：成分从哪来

### 1.1 组件本身

- 锭的成分存在物品组件 **geometallurgy:ingot_composition** 上，类型 **DataComponentType&lt;Map&lt;String, Double&gt;&gt;**，
  **persistent + networkSynchronized**（item/ModComponents.java:59-67）。
- 组件值是**质量分数**（总和 1.000），**不是 mol**：ModComponents.java:52 明写「物质 id → 质量分数（总和 1.000，对齐到百分位）」。
  mol 是另一本账（chemical/MolStock.java:52，INGOT_MOL = 0.1，一件锭 = 0.1 mol），**只在化学侧用，转换台不碰**。
- **机器按物品 id 决定收不收**：26.x 的原版 Ingredient 已收成纯物品集合、看不到组件（recipe/IngotCastingRecipe.java:19-26 有完整说明）。
  所以「标准锭 = 独立物品 id」同时解决了「独立物品」与「按物品名拒收」两件事。

### 1.2 量化网格（影响概率的第三位小数）

| 归一化器 | 位置 | 网格 | 性质 |
|---|---|---|---|
| **Ingots.normalize** | metal/Ingots.java:418-452 | **1%**（Math.round(share*100)/100） | 零头记在占比最大的一项；锭物品走这条 |
| **CompositionMath.normalize** | proto/CompositionMath.java:73-92 | **0.1%**（千分位，最大余数法） | 矿浆 / 物种等走这条 |

两者不一致，且 Ingots.normalize 的注释写「千分位」、代码实际是百分位（metal/Ingots.java:413-416 与 432 行对照）。
- 本稿**按 1% 网格**算概率（成分百分比都是整数）。
- 「以哪一条为准」列入待确认（清单第 8 条）。

### 1.3 「金属」怎么判

- 仓库现有两处金属判定：**MetalSeries.ORDER**（20 种，metal/MetalSeries.java:25-29、isKnownMetal :55）与
  **Substance.isMetal**（proto/Substance.java:144-147）。
- **两处不一致**：titanium、vanadium、rare_earth 在 Substance 里登记为 **nonMetal**（proto/Substance.java:67-71），现实里都是金属。
- 后果：直接用 Substance.isMetal 当窗口谓词，**标准钛锭 / 含硅铝锭 / 稀土相关的入料永远过不了门槛**。
- 本稿的全局谓词（纯类，不 import net.minecraft）：

~~~
boolean isMetalKey(String id) {
    return Substance.isMetal(id)          // 20 种主族/过渡金属
        || MetalSeries.isKnownMetal(id)   // 同一批，冗余兜底
        || RareEarth.isRareEarth(id)      // 稀土按金属算
        || id.equals("rare_earth");       // 并项后的键（Ingots.group）
}
~~~
  「钛 / 钒 / 稀土是否改登记为金属」列入待确认（清单第 9 条）。

## 二、表一：族 → 标准锭规格表

### 2.1 两级模型

- **一级：族**（9 族）——铁基 ferrous、铜基 copper、铝基 aluminum、铅锡 solder、镍基 nickel、钛基 titanium、难熔 refractory、稀土 rare_earth、
  **贵金属 noble（金 / 银，本轮新增——它们不是合金，见 §2.3 读法 ①）**。
  族只用于**组织、解锁与词缀路由**，不直接决定任何判定。
- **二级：具体标准锭**——每种一个独立物品 id、一套固定成分、一个入料窗口、1~2 类用途。
- 族内成员**成分差别很大**（黄铜 Cu63Zn37、青铜 Cu88Sn12、白铜 Cu75Ni25），**窗口互斥**是硬要求（§3.5 自检）。

### 2.4 每锭入料窗口与概率区间（表 1-B）

**窗口 = 一组约束（元素 ∈ [下限, 上限]，1% 网格整数）**。窗口必须满足：**A 的下限之和 A_min > 70%**（落实规则 4），
且**同族成员的窗口互不重叠**（§3.5 自检）。

概率区间的推导：P = 0.70 × Π(1 − f_D) − Σ f_H。窗口把 A 锁在 ≥ A_min，剩余质量 r ≤ 1 − A_min 只能分给 D 与有害项；

### 2.6 v1 名单（本轮调整：**去掉青铜**）与理由

**v1 = 标准钢锭 + 标准黄铜锭 + 标准硬铝锭 + 标准导电铜锭 + 标准锰钢锭 + 标准钨钢锭 + 标准金锭 + 标准银锭。**

> 青铜**从 v1 移除**（降为 v1.1 备选）。理由见本节末「为什么青铜被换掉」。

| # | 标准锭 | 固定成分（%） | 入料窗口 | 用途 | 一句话：**为什么比青铜更值得做** |
|---|---|---|---|---|---|
| 1 | 标准钢锭 | Fe 98 + C 2 | Fe ≥ 71，C 0~3 | 机壳 / 传动（机器本体） | 青铜只做滑动摩擦副，钢撑**整个机器本体**（§2.7 里机器本体是最大的标准锭消耗项）。 |
| 2 | 标准黄铜锭 | Cu 63 + Zn 37 | Cu ≥ 60，Zn 25~45 | 导管 / 电气（机器本体） | 黄铜同时占**流体**与**电气**两个类目，青铜只占传动一个。 |
| 3 | 标准硬铝锭 | Al 94 + Cu 4 + Mg 1 + Mn 1 | Al ≥ 90，Cu 3~6，Mg ≥ 1 | 轻质机壳 | 硬铝把机器减重**并**顺手把窗口收到最严（P ≥ 64.00%），是「严窗口 = 省成本」的样板。 |
| 4 | **标准导电铜锭** | Cu 100 | Cu ≥ 71 | **电气 / 导电件** | 纯铜导电率约为青铜的 3 倍；青铜做导线是**用错材料**，现实里没有青铜导线。 |
| 5 | **标准锰钢锭** | Fe 87 + Mn 12 + C 1 | Fe ≥ 71，Mn 8~16，C 0~2 | **传动** / 耐磨 | Hadfield 高锰钢**加工硬化**后比锡青铜硬得多，直接顶替青铜的齿轮/轴承位，且复用钢的 Fe 入料线（不用锡）。 |
| 6 | **标准钨钢锭** | Fe 82 + W 15 + C 3 | Fe ≥ 71，W 10~20，C 0~5 | **工具** / 耐磨 | 青铜完全做不了切削刀具；钨钢让「硬料 → 工具」这条线在 v1 就有入口（钨钴硬质合金仍留 v3）。 |
| 7 | **标准金锭（100%）** | Au 100 | Au ≥ 71 | **电气** / 耐蚀 | 金不氧化：触点寿命是青铜的**数量级**差别；且 100% 成分让精炼第一次有明确回报（98% → P 68.00%，§3.4）。 |
| 8 | **标准银锭（100%）** | Ag 100 | Ag ≥ 71 | **电气** / 电极 | 银是**导电率最高的金属**；青铜电极在电解槽里会溶解污染电解液，银不会。 |

**为什么青铜被换掉（三句）**：
1. 青铜的**功能位**（传动）被锰钢以更硬的材料、更厚的入料来源（铁 vs 锡）顶替；
2. 青铜的**电气位**本来就该由导电铜/银承担（现实里青铜不用于导电），继续留着会把「导管/电气」两个类目搅在一起；
3. 青铜的「同族区分演示」价值可以由**黄铜 vs 导电铜**（Cu-Zn vs Cu）继续承担，不必占用 v1 名额。

**v1.1**：标准青铜锭（传动备选）、标准铸铁锭（复用钢同一条 Fe-C 线，只改碳窗口）、标准铅锡焊料锭（接合）。
**v2**：不锈钢、白铜、铝硅、铝镁、铅锑、镍铬。
**v3**：高速钢、蒙乃尔、钛合金、钨钴、钨镍铁、稀土磁体（磁体需**硼砂矿→硼**，§2.8）。
优先级本身列入待确认（清单第 5 条）。

## 三、表二：公式与样例表

### 3.1 三类判定 + 窗口

对某一标准锭规格 Spec = (id, 族, 固定成分, 窗口, A, D)：

| 类别 | 判据 | 公式里的作用 | 例（标准钢） |
|---|---|---|---|
| **合金金属（有意成分）** | 键 ∈ A（且通常受窗口约束） | **不扣** | 铁、碳 |
| **非有害杂质（纯稀释剂）** | 键 ∈ D | **乘性扣**：×(1 − f) | 锌 |
| **有害杂质** | A、D 之外的一切键 | **加性扣**：−f（百分点） | 硫、磷、石英（渣/氧化物）、铜（其他金属） |
| **窗口（过关条件）** | 每个约束都满足（下限 ≤ f ≤ 上限） | 不满足 ⇒ **不合格**（停机、不扣电） | 青铜：Cu ≥ 70 且 Sn 8~20 |

### 3.2 可执行伪码（纯类，可离线打印任意成分的 P 与匹配结果）

> 设计约束：这个类**不许 import net.minecraft**（照 proto/CompositionMath.java 的先例），只需「物质 id → 中文名 / 是不是金属」两张纯表。

~~~
record Bounds(double min, double max) {}          // 单位 = 分数（0.01 步进）

record Spec(String id, String family,
            Map<String, Double> target,           // 固定成分
            Map<String, Bounds> window,           // 入料窗口
            Set<String> alloyMetals,              // A
            Set<String> benignWhitelist) {}       // D

double BASE = 0.70;

boolean isMetalKey(String id) {
    return Substance.isMetal(id) || MetalSeries.isKnownMetal(id)
        || RareEarth.isRareEarth(id) || id.equals("rare_earth");
}

enum Kind { ALLOY, BENIGN, HARMFUL }

Kind classify(String key, Spec spec) {
    if (spec.alloyMetals().contains(key))      return Kind.ALLOY;   // 有意成分，不扣
    if (spec.benignWhitelist().contains(key))  return Kind.BENIGN;  // 纯稀释剂，乘性
    return Kind.HARMFUL;                                             // 其它一切，加性
}

// 窗口：每个约束都要满足；比较在千分位整数上做，避免 double 误差（见 §3.4 浮点陷阱）
boolean windowPass(Map<String, Double> comp, Spec spec) {
    for (var e : spec.window().entrySet()) {
        long units = Math.round(comp.getOrDefault(e.getKey(), 0.0) * 1000.0);
        long lo = Math.round(e.getValue().min() * 1000.0);
        long hi = Math.round(e.getValue().max() * 1000.0);
        if (units < lo || units > hi) return false;
    }
    return true;
}

// 必要门槛（规则 4 的落实）：A 合计 > 70%（整数比较）
boolean alloyGate(Map<String, Double> comp, Spec spec) {
    long units = 0;
    for (var e : comp.entrySet()) {
        if (spec.alloyMetals().contains(e.getKey())) units += Math.round(e.getValue() * 1000.0);
    }
    return units > 700;
}

// 概率：P = 0.70 × Π(1 − f_稀释剂) − Σ f_有害，clamp [0,1]
double probability(Map<String, Double> comp, Spec spec) {
    double product = 1.0, harmful = 0.0;
    for (var e : comp.entrySet()) {
        switch (classify(e.getKey(), spec)) {
            case BENIGN -> product *= (1.0 - e.getValue());
            case HARMFUL -> harmful += e.getValue();
            default -> { }
        }
    }
    return Math.max(0.0, Math.min(1.0, BASE * product - harmful));
}

// 自动匹配（§5.7 方案 A）：在所有窗口通过且合金门槛过的候选里，取 P 最高；
// 并列时取与固定成分 L1 距离最小的那个；再并列按规格表稳定顺序。
record Match(Spec spec, double p, double distance) {}

Match bestMatch(Map<String, Double> comp, List<Spec> specs) {
    Match best = null;
    for (Spec s : specs) {
        if (!windowPass(comp, s) || !alloyGate(comp, s)) continue;
        double p = probability(comp, s), d = l1(comp, s.target());
        if (best == null || p > best.p()
                || (p == best.p() && d < best.distance())) {
            best = new Match(s, p, d);
        }
    }
    return best;   // null = 不合格（停机、不扣电、不销毁）
}

// 界面拆解（四行显示用）
record Breakdown(double base, double diluentFactor, double harmfulSum, double finalP) {}
~~~

### 3.3 有效区间：理论上限 / 下限

| 量 | 推导 | 结果 |
|---|---|---|
| **理论上限** | Π ≤ 1 且 Σ有害 ≥ 0 ⇒ P ≤ 0.70 | **70.00%**（只有零稀释剂、零有害才拿到） |
| **单锭理论下限** | 窗口锁住 A ≥ A_min ⇒ 剩余 ≤ 1 − A_min 全给有害项 | **P_min = 0.70 − (1 − A_min)**，逐锭见表 1-B |
| **全库最低下限** | 最松窗口 = 标准钢（A_min = 71%） | **41.00%** |
| **全库最高下限** | 最严窗口 = 标准硬铝（A_min = 94%） | **64.00%** |
| 超过 70% 的唯一途径 | 「增概率改件」加算，封顶 | ≤ 100.00% |

**结论（写入界面文案）**：无改件时 **P ∈ [41.00%, 70.00%]**（逐锭区间见表 1-B）；**P = 0 不可达**，故不设「概率为 0，拒收」。

> **口径定稿（本轮用户确认）= A**：门槛就是「**该合金配方内的金属合计 > 70%**」——
> **只看该规格自己的合金金属集合 A**，不采用「任意金属物种合计 > 70%」的宽读法。
> 保留反证备查：宽读法下错误金属既是金属、又是有害项，P 可以归零 ——
> 例：铁 20% + 碳 2% + 锌 8% + 铜 70% ⇒ 金属合计 100%，P = 0.70 × 0.92 − 0.70 < 0 → clamp 0。
> 而在 **A 口径 + 窗口模型**下，这种料连钢的 Fe ≥ 71 窗口都过不了，直接判不合格（停机、不扣电），
> 所以全库下限仍是 **41.00%**（最松窗口 = 标准钢 A_min = 71%），**P = 0 不可达、仍不需要「P=0 拒收」**。

### 4.3 五个改件：配方、词缀、效果

### 4.5 槽位实现约束（bug#35 的教训，必须写进实现轮）

- **现场教训**：bug#35 里客户端与服务端数出不同槽数而错位。根因原文：
  「真物品槽的增删不能按 solutionMode() 做 —— 该方法在客户端构造菜单时读到的 ContainerData 还是全 0，
  服务端与客户端会数出不同的槽数而错位。」（docs/bug-log.md:379-381；docs/科技线-v1.md:1390-1392）
  后续同类修复也强调「**没有新增 / 删除任何 addSlot**」（docs/科技线-v1.md:1778-1779）。
- **硬规则**：
  1. **addSlot 的数量与坐标必须是常量**：按**最大槽数**建菜单（物品槽 输入 3 + 输出 3 + 改件槽 5），
     **禁止** if (hasMotor) addSlot(...) 或 for (i < activeCount) addSlot(...) 这类依赖机器状态的建槽；
  2. 可变性只走 **Slot#isActive()** 与**界面跳过绘制**（不画非活跃槽与标签）；
     isActive() 读同步过来的「已装改件」位图（ContainerData / 方块实体同步数据），读取失败时**保守回落到默认（1 进 1 出）**；
  3. isActive() 两端可能因同步延迟短暂不同，但**槽位下标集合不变**，不会出现 bug#35 那种下标错位；
     点击与绘制按「服务端最终说了算」再回正；
  4. 改件槽数组**长度固定 5**，不随版本增删（存档兼容；与 APPEND ONLY 惯例一致，见 proto/Substance.java:98-104 注释）。
- **回归点**：装 / 卸任意改件前后，菜单槽位总数恒定；客户端与服务端一致（§4.8 T13）。
- **实现前先核实 API**：照 docs/测试场地.md:25 的先例「先 javap 核实 26.x 签名，不要凭 1.21 经验写」。

### 4.7 机制问题：**自动匹配 vs 先指定目标**（必须由用户裁决）

> 修正 2 带来的一簇合金后，这是最关键的机制分叉。以下两案都写清流程、优点、代价；本稿**建议方案 A**，但保留 B 作为「高级模式」。

**方案 A（建议）：按输入成分自动匹配到最接近的标准锭**

- **流程**：入料进槽 → 遍历标准锭表 → 取「窗口通过 + 合金门槛过」的候选 → 取 P 最高 → 界面显示「将产出：标准青铜锭 70.00%」→
  运行 100 刻 → 成功给该锭；**没有任何候选 ⇒ 不合格，停机不扣电**。
- **优点**：
  1. 玩家**不需要先知道每族的窗口**（喂 Cu+Zn 自然得黄铜、喂 Cu+Sn 自然得青铜，§2.5 已自检）；
  2. 与「废锭有出口」的设计意图一致 —— 拿到的料直接丢进去，机器自己认；
  3. 同族区分由窗口机械完成，不依赖玩家知识；UI 只多一行预览。
- **代价 / 必须配套**：
  1. **需要「发现 / 解锁」门槛**，否则第一天就能用废料做出 v3 高端锭。建议：每个规格首次成功产出后进入手册与匹配表；
     未解锁的规格不参与匹配（或降级为不合格）—— 具体机制待确认（清单第 1 条的配套项）。
  2. **候选歧义**：同族两窗口若重叠，会出现「不知为何出了另一种锭」。必须做**启动期窗口互斥自检**（任两窗口交集非空 ⇒ WARN），
     并把「P 最高 → L1 距离最小 → 表序」作为唯一裁决顺序，两端同解（测试点 T14）。
  3. **不能主动挑便宜产物**：若两种都通过，玩家只能拿 P 最高的那种。可加「目标锁定」开关（默认关）作为补充。
  4. **数值面集中**：窗口表成为唯一的玩法平衡面，改动牵一发动全身。
- **补充建议**：把「目标锁定」做成**可选的高级模式**（UI 一个下拉，默认「自动」）；锁定后只在该规格的窗口内计算 P，
  窗口不过则显示不合格。这样两案的优点都能拿到。

**方案 B：玩家先指定目标标准锭，再按贴近度算概率**

- **流程**：UI 先选目标（手册点选 / 下拉，未解锁不可选）→ 对固定成分算贴近度 → 概率 = 0.70 × Π(1 − f_D) − Σ f_H − 偏离惩罚。
- **优点**：可控、可解释、可存档、天然防越级（未解锁就选不了）；玩家可以刻意「凑成分」。
- **代价**：
  1. 玩家**必须先知道窗口**（否则喂 Cu+Zn 选青铜会白费电与料）—— 与「玩家也不是傻子」不冲突，但学习成本落在玩家身上；
  2. UI 多一步选择，且选错不会在投入前被发现（自动匹配会直接把 Cu+Zn 变成黄铜）；
  3. 需要额外定义「贴近度/偏离惩罚」公式（本稿的备选：把 |f_i − target_i| 当作有害项加算，系数 k 待定）—— 又是一处平衡面。
- **本稿倾向**：**A 为主、可选锁定为辅**。理由是修正 2 的动机（族内种类差别大）需要一个**不需要玩家背表**的默认路径；
  但「玩家也不是傻子」这句也说明不应把选择权完全拿掉，所以保留锁定开关。

> 这个机制分叉**单列进待确认清单第 1 条**，并附上本稿建议与代价，等用户裁决后再进入实现轮。
