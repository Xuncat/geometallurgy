# 产线成本账（ProductionCost 模型 · 分析轮）

> 起因：上一轮我说「一桶酸（15 mol）能处理 ~75 个锭（0.1 mol 一个），所以酸几乎不要钱」，
> 用户回「**制造一桶酸同样要付出大量代价**」。他是对的 —— 判断一个消耗品贵不贵，
> 必须同时算**造它的递归成本**与**它能干多少活**。这份账就是这两半。
>
> 本轮**只做分析 + 一个纯 Java 成本模型 + 本文档**：没有改反应、物种、世界生成、mol 常数或机器行为。
> 复算脚本是一次性 harness（已按约定删除），模型本体在 `chemical/ProductionCost.java`。
>
> **2026-10-16 补注**：随后一轮电力正确性修复改了 `ProductionCost.MACHINE_STEP` 的电解炉熔盐档
> （288 → 360 FE/单位，铝土矿实值），并修了离心机 / 矿脉抽取机 / 溶液电解的扣电口径。
>
> **2026-10-17 用户调参轮（本轮，全表重算）**：抽取机 256 → 1024 FE/t（+20480 FE/矿根）、
> 粉碎机 128 → 256 FE/t（18 → 36 FE/单位@莫氏5）、离心机/磁选机额定 64 → 128（8 → 16 FE/单位）、
> 还原炉改**逐配方功率**（其中 13 条路线改成**试剂驱动 0 FE**，见 §二.3）、电解炉熔盐档逐配方
> （80 → 160 FE/t 基准、300 → 600 上限）、溶液电解由平铺 120 改成**逐反应单价**（150/180/260/300/520）。
> 本文**所有 FE 数字都变了**，下面每一张表都给"前 → 后"；由一次性 harness 复算，harness 已删。
> 新增缺口：模型仍**不记还原剂**，而试剂驱动路线的成本全压在还原剂上（§六.2）。

## 一、模型：`chemical/ProductionCost.java`

### 1.1 口径

- **节点** = `ReactionGraph.nodes()` 的 120 个：79 个 `Chemical` 物种 + 41 个非化学节点
  （原矿 / 精矿 / 精矿粉 / 化合物 / 金属锭）。
- **边** = 151 条超边：107 条化学反应（`MolRecipes.all()`：57 显式 + 50 规则生成）+ 44 条桥接机器步骤。
- **目标**：给定物种 id / 节点 id，反向沿超边求「生产 **1 个单位**」的成本。
  化学物种的 1 个单位 = **1 mol**；锭 / 粉按 `MolStock.INGOT_MOL = 0.1` 折算；
  桶按 `MolStock.BUCKET_MOL = 15` 折算。成本对产量线性。
- 每条路线累加四类量：
  1. **矿根 mol**（`roots`）：回溯到 `ReactionGraph.ORE_ROOTS`（23 个）为止，逐层按反应系数
     `c_r / c_p` 折算；这是「上游矿石量」，**也正是矿脉丰度重调时该看的量**（不是区块频率）；
  2. **机器刻数**：化学反应 = `推进份数 ÷ 有效速率`，
     `有效速率 = 机器吞吐上限 × Reaction.rate() × 修正`；
  3. **FE**：只在机器真正计费处记（见 §二）；
  4. **反应份 / 桥接步 / 边数**。
- **路线选择**：Bellman-Ford 式迭代松弛，按目标函数取最优。提供三种口径：
  `ORE_FIRST`（稀缺矿根 mol 优先 → 再电 → 再时间；默认）、`FE_FIRST`、`TICKS_FIRST`。
  同一物质有多条路线时，三种口径的差异本身就是平衡信息（见 §四 HCl）。

### 1.2 关键假设（都从代码常量抄来，不自造数）

| 量 | 取值 | 出处 |
|---|---|---|
| 反应釜 / 搅拌器吞吐 | 1.0 份/t | `AbstractReactorBlockEntity.RATE_PER_TICK` |
| 电解炉溶液档吞吐 | 0.5 份/t | `SmelterBlockEntity.SOLUTION_RATE_PER_TICK` |

> 可选的湿法置换炉在本图里没有任何边用到，所以不参与比价。

### 1.3 环的守卫（图里真的有环）

- **第一层：迭代上限**。松弛到不动点就停；到达 `MAX_ITERATIONS = 512` 仍在变，
  `Result.hitIterationCap()` 置真并在 `describe()` 里打警告 —— **绝不静默死循环**。
  本轮三种口径、全部目标均**未触上限**。
- **第二层：回溯上限**。重建路线时对已访问节点剪枝（`MAX_TRACE_DEPTH = 64`），
  遇到环打 `(cycle)`，不递归爆栈。
- 实际遇到的环：
  - `2 NaOH → Na2O + H2O` ↔ `Na2O + H2O → 2 NaOH`（净零环，NaOH 不走这条）；
  - Ostwald：`4 HNO3 → 4 NO2 + …` ↔ `3 NO2 + H2O → 2 HNO3 + NO` ↔ `2 NO + O2 → 2 NO2`；
  - 氨的**净消耗环**：`NH3 + HNO3 → NH4NO3`、`2 NH4NO3 → 2 N2 + …`、`N2 + 3 H2 → 2 NH3`。
    每轮只回收 0.5 份 NH3，线性方程 `c = 0.5c + X` 有解，模型给出的固定点是有效的；
    路线打印在此处打 `(cycle)` 只是剪枝，不代表成本算错。

> 抽取机 ×4 把"矿 vs 电"的取舍表压成了"矿就是电"。

## 三、用户真正在意的那一半：成本 vs 吞吐

### 3.1 一桶酸能处理多少个锭（`ProductionCost.ingotsPerBucket`）

| 酸 | Zn | Mn | Al | Fe | Cu |
|---|---|---|---|---|---|
| 盐酸 HCl | **75** | **75** | 50 | 无反应（铁被规则禁用） | 无（H 之后） |
| 硫酸 H₂SO₄ | **无反应** | 无 | 无 | 无 | 无 |
| 硝酸 HNO₃ | **无反应** | 无 | 无 | 无 | 无 |
| 氢氧化钠 | 无 | 无 | 无 | 无 | 无 |
| 氨 | 无 | 无 | 无 | 无 | 无 |

口径：`Mⁿ⁺ + 酸 → 盐 + H₂` 这条边（规则 5 生成）里 `酸系数 / 金属系数 × 0.1`。
Zn/Mn 是 `M + 2 HCl`（0.2 mol/锭），Al 是 `2 Al + 6 HCl`（0.3 mol/锭）。

### 3.2 投产比（盐酸，手挖矿根）

| 路线 | FE 加工/桶（前 → 后） | 稀缺矿根/桶 | 处理 Zn/Mn 锭 | FE/锭（前 → 后） | 矿根/锭 | 对照：造该锭本身（前 → 后） |
|---|---|---|---|---|---|---|
| ORE_FIRST（氯碱） | 4620 → **9165** | 15 | 75 | 61.6 → **122.2** | 0.2 | 4.0 → **10.8** FE、0.1 闪锌矿 |
| FE_FIRST（岩盐+硫酸） | 2820 → **3615** | 22.5 | 75 | 37.6 → **48.2** | 0.3 | 同上 |

**结论（这才是用户要的那个数）**：
- 一桶盐酸能处理 75 个 Zn/Mn 锭，但**造这桶酸要花 3615~9165 FE 加工电 + 15~22.5 个矿根 mol**；
- 摊到每个锭上是 **48.2~122.2 FE + 0.2~0.3 矿根**，而**造这个锭本身要 10.8 FE + 0.1 闪锌矿**；
- 也就是说，**「用酸处理一个锭」这一步的电是「造这个锭」的 4.5~11 倍，矿石量是 2~3 倍**。
  酸**不是**几乎免费 —— 上一轮只算了吞吐、没算生产，结论正好反了。
- 注意倍数被**两头同时拉近**了：酸涨了 1.3~2×，而锌锭自己涨了 2.7×（闪锌矿还原 54 → 108 FE/t）。

## 四、不平衡清单（带数字）

1. **化学反应机完全不耗电（最根本的一条）**。反应釜、搅拌器没有 `energy` 字段，
   所以「S + O₂ → SO₂」「2 SO₂ + O₂ → 2 SO₃」「SO₃ + H₂O → H₂SO₄」「NH₄Cl + NaOH → NH₃」
   这些步骤的 **FE = 0**（本轮仍然没给它们加电，见 docs/耗电一览.md §二.4）；
   整条硫酸链除电解制氧外一度电都不花（硫酸 450 FE/mol 全部来自 O₂，其中 O₂ 300）。
   电只花在**电解**（逐反应 150~520 FE/mol 反应物）与**选矿/冶金机器**上。
   → 后果：化学部分几乎免费，成本全压在矿根与少数电解步上；「酸贵」本质上等于「矿石与电解贵」。

2. **矿石是真正的货币，而且抽取机一开就压倒一切**。每桶酸 15~22.5 个矿根单位；
   走抽取机就是 **307200~460800 FE/桶**（旧 76800~115200），**是加工电的 30~44 倍**。
   而且本轮之后「矿少的路线」自动等于「电少的路线」（矿根 20480 FE 一个）——
   ORE_FIRST 与 FE_FIRST 在计开采电时**收敛到同一条路线**。
   在这条数下，「酸便宜」与「酸昂贵」都只是矿脉经济的一个回声。
   → 矿脉丰度重调（另一名代理在做）会**直接**改变这张账，本模型只用 mol 量、不用区块频率。

3. **五种酸里只有盐酸能处理金属锭，其余四种吞吐为 0**。
   `ReactionRules` 的跳过清单里 `SPECIES_MISSING` 93 条，缺的正是硫酸盐 / 硝酸盐
   （`ZnSO₄`、`Al₂(SO₄)₃`、`Zn(NO₃)₂`、`Al(NO₃)₃` …）。
   所以「硫酸/硝酸能溶解多少金属」在这个版本里**没有答案**：它们只在别的支路（HF、硝石、中和）里有用途。
   → 若想让每种酸都有「处理金属」的出口，得补盐物种；不补就是设计选择（盐酸 = 唯一浸出酸）。

4. **盐酸两条路线是典型的「矿 vs 电」取舍**：
   - 氯碱路线（H₂ + Cl₂）：**1 岩盐 + 22.5 水/桶**、9165 FE —— 省矿、费电（氯碱单价 120 → 260）；
   - 硫酸路线：**1 岩盐 + 0.5 硫 + 2 水/桶**、3615 FE —— 省电、多矿（硫）。
   `ORE_FIRST` 选前者、`FE_FIRST` 选后者（不计开采电时）。**没有哪条严格占优**。
   **但本轮给出了那个汇率**：把抽取机开进账，矿的价格就是 20480 FE/mol，
   氯碱路线立刻同时赢在两边 —— 「矿与电的汇率」由抽取机常数**显式地**给出了。

5. **氨的昂贵是结构性的**：`FE_FIRST` 走 `NH₄Cl + NaOH`，每桶要 **15 岩盐 + 15 硇砂 + 15 水**、
   8280 FE（旧 3840：氢氧化钠涨到 536 FE/mol，而这条路线的电费几乎全是烧碱）、30 个桥接步；
   `ORE_FIRST` 改走「硝石 → 硝酸 → 硝酸铵 → 氮 → Haber」的净消耗环，矿根 22.5、FE 10365、
   **机器刻 1141**（Haber 速率为全表倒数第二，0.02 份/t）。氨是这五种里**又贵又慢**的那个。

6. **硫酸的瓶颈是接触法那一步**：`2 SO₂ + O₂ → 2 SO₃` 速率 0.03（全表倒数第三），
   即便钒催化剂在位（×4）+ 搅拌（×1.25），有效速率也只有 0.15 份/t；
   一桶硫酸 319 刻里，**50 刻**卡在这一步。电是便宜的、时间不是。

7. **硝酸是五种里单位最便宜的**（241 FE/mol，旧 188），但它依赖硝石（`natratine`）作根；
   硝酸路线与盐酸 FE_FIRST 路线电耗相同（都是硫酸 + 矿物复分解），成本差别只在根。

8. **铝的电解是真的贵**（每件锭 **85.6** FE，是锌锭的 7.9 倍、铁的 16.5 倍），
   来自 `Metallurgy` 路线表里熔盐电解的绝对功率（铝土矿 160×4.20 = 672，被 maxDraw 600 截断）
   —— 这一条是**有意的**、不是失衡。

## 五、本轮的"动哪个常数"：建议 → 实际做了什么

上一版本节的建议在本轮被用户逐条采纳（`SOLUTION_FE_PER_MOL` 那条**被更强的做法取代**）：

| 旧建议 | 本轮实际 |
|---|---|
| 抬 `SOLUTION_FE_PER_MOL=120` | **删掉这个平铺常量**，改成**逐反应单价**（水 150 / 锰酸钾 180 / 氯碱 260 / 钾碱 300 / HF 520），并加启动断言防漏标 |
| 让矿石成为约束 | 抽取机 256 → **1024 FE/t**（+20480 FE/矿根），加工电与开采电的比例变成 1 : 30~44 |
| 不动反应釜 / 搅拌器 | **维持 0 FE**（理由见 docs/耗电一览.md §二.4） |
| （未建议）稳定金属的电价 | 还原炉改**逐配方功率**，13 条燃料驱动力路线归零、其余电炉路线 ×2；电解炉熔盐档逐配方（基准 ×2、上限 ×2） |
| （未建议）选矿段电价 | 粉碎机 ×2（每次操作成本同步重推）、离心机 / 磁选机额定 ×2（语义与窗口不变） |

**给下一轮的建议（不改）**：
- 若觉得「铁/铜加工电为 0」太轻：把 `Metallurgy` 里那两条还原路线的 FE/t 从 `0.0` 改成 `80.0`
  （一行一个矿），它们就回到"电 + 碳"的混合口径。
- 若想让"用酸处理锭"这一步更有分量：抬溶液的逐反应单价即可（每个反应一行），
  或用 `Fe + H₂SO₄` 补盐把硫酸 / 硝酸的吞吐打开（见不平衡 3），让更多酸参与分摊。

## 六、模型不覆盖什么（明确的缺口）

1. **可逆反应的平衡产率**：模型按化学计量**完全转化**算。合成氨 K=0.25、
   `CaCO₃/MgCO₃` 焙烧 K=6、`Al(OH)₃` 焙烧 K=6、`NaHCO₃` K=8、
   `Cl₂ + H₂O` K=0.25 的实际单次转化都 <100%，成本被**系统性低估**。
   （氨的 Haber 路线若按 K=0.25 折算，还要再乘一个数倍因子。）
2. **选矿 / 冶金的收率与杂质**：`metal/Metallurgy` 的 `recoveryScale`（0.70~1.0）、
   `carryScale`（1.0~2.0）、碳残留（`CARBON_CARRY`）、矿石品位、掷骰概率；
   桥接边一律 1:1 抽象。
   **本轮起这条缺口变大**：还原炉有一批路线是**试剂驱动**（0 FE/t），成本全压在还原剂当量上
   （`Metallurgy` 路线表：铁 1.60、锡 1.70、白铅矿 1.85、孔雀石 1.90、自然金属 0.40 …），
   而本模型**只记电**。所以铁 / 铜 / 锡 / 铅 / 贵金属这几行的 FE 是**不完整成本**；
   还原剂当量表见 docs/耗电一览.md §2.3。
   **2026-10-17 补注（bug#37）**：还原剂的主路是**碳系**（煤炭 / 木炭 / 碳粉 / 碳棒），
   金属只是可选替代；「金属必须比目标活泼」这条闸门只属于置换炉，不在还原炉。
3. **矿浆 mB ↔ mol 的接缝**：桥接边把「1 单位矿石」当「1 单位物种」，
   没有 mB→mol 换算（设计稿 §六.7 的已知未决项）。因此「矿根 mol」是**抽象的化学计量单位**，
   不是开采出来的矿石桶数。
4. **玩家劳动**：手挖矿石的 FE 记 0，但耗时/跑图完全没算；自动化的桶搬运、配置器操作也没算。
5. **燃料与电力基础设施**：FE 只记用电设备的耗电，没记发电燃料、电池 50% 出入损耗、
   线损。若要把 FE 折成煤，按 `CoalGeneratorBlockEntity` 1 煤 = 200 × 64 = **12800 FE** 换算
   （每桶盐酸 ≈ 0.28~0.72 煤；走抽取机则 ≈ 24.7 煤 —— 旧口径是 6.4）。
6. **容器 / 催化剂物品造价**：桶（4 铜锭 / 4 玻璃 / 4 铅锭 / 4 黏土+4 砖）、碳棒、钼棒
   都按「有一只、不消耗」处理，配方成本不在模型内。
7. **矿脉丰度 / 区块频率**：**刻意不使用**。另一名代理正在重调矿脉生成，
   本模型只输出 mol 量（§二），丰度变化请以 mol 为入口重算。
8. **湿法置换路线的成本**：本图没有任何边用 `Machine.DISPLACEMENT`，
   置换炉的功率（现在写死 0）、活泼金属还原剂消耗都不参与比价。

## 七、没能验证的 / 受限的

- **未实机运行**：模型是在普通 JVM 里对 `MolRecipes.all()` + `ReactionGraph` 复算的，
  没进世界核对机器的真实 tick 顺序（例如反应釜「先收桶还是先反应」的边界 tick）。
- **机器电耗按额定值记**：磁选机实际 `MAX_DRAW=512`，且其 `tick()` 仍是
  **`min(energy, MAX_DRAW)` 通电即扣**（空转也扣是**特性、保留**，将来由永磁磁铁升级处理，见 bug#29）。
  模型按「额定 128 FE/t」记，所以对磁选机是**下限**；若按 MAX_DRAW 记，选矿段 FE 要再乘约 4。
  离心机原本的空转扣电缺陷已修（改为有活可干才取电），按额定记与实际一致。
- **冶炼按"逐配方"记但只记了 6 条桥接边**：模型只覆盖 `ReactionGraph` 里真正连到金属锭的
  6 条冶炼桥接边；表里其余 20+ 条矿物的还原 / 电解路线不进本图（它们不在最优路上），
  所以本模型的冶炼口径是"本图选中的那一条"，不是整张路线表的平均。
- **速率修正按「最好情况」**：催化剂总是放在位（×4）、搅拌总是开着（×1.25）。
  没催化剂 / 不搅拌时，本文所有 ticks 会变长（慢 1.25~5 倍）。
- **矿物摩尔质量的取整**：`Chemical.isMassBalanced` 容差 1 g，个别反应每份有亚克级残差；
  对成本为 0 影响，但报告里的「mol 数」来自整数系数，不是称重。
- **未验 `Chemical` 89 种物种的完整表**：只读了前 15 + 本轮相关的；成本表覆盖了
  酸 / 碱 / 氨 / 硝酸 / 金属粉 / 锭 / 稀土氧化物。

## 八、怎么复算

```java
// 纯 Java，无 net.minecraft 依赖；harness 已删，下面是调用形状
ProductionCost.Result r = ProductionCost.bucketCost("hydrochloric_acid",
        ProductionCost.Objective.FE_FIRST);          // 1 桶 = 15 mol
System.out.println(ProductionCost.describe(r));       // 矿根明细 + 完整路线 + FE/刻/份
double n = ProductionCost.ingotsPerBucket("hydrochloric_acid", "zinc"); // 75
```

- 不收敛时 `describe()` 会写「达到迭代上限 512 仍未不动点」；本轮未出现。
- 想按「矿根全部走抽取机」复算：把 `DEFAULT_CHARGE_ROOT_EXTRACTION` 临时置 `true`
  （或调用四参 `evaluate(..., true)`），FE 会加上 **20480**/矿根 mol。
- 冶炼那 6 条桥接边的功率手抄在 `ProductionCost.SMELT_STEP`（键 = 桥接边 id）；
  逐反应电解单价直接读 `MolBalance.Reaction.fePerMol()`，不另抄。
