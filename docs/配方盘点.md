## 问题清单（逐条给证据）

### 1. 明显不合理的配方

**1.1 「铁钻头」`drill_bit_iron`（用户点名的那条）**

当前配方（`drill_bit_iron.json`）：

```json
{ "type": "minecraft:crafting_shaped",
  "pattern": [ "III", "I  " ],
  "key": { "I": "minecraft:iron_ingot" },
  "result": { "id": "geometallurgy:drill_bit_iron", "count": 1 } }
```

同类三档（同一文件夹）：

| 钻头 | 配方 | 材料数 |
|--|--|--|
| `drill_bit_stone` | `SSS` / ` I ` | 3 石 + 1 铁 |
| `drill_bit_gold` | `GGG` / ` I ` | 3 金 + 1 铁 |
| `drill_bit_diamond` | `DDD` / ` I ` | 3 钻石 + 1 铁 |
| **`drill_bit_iron`** | **`III` / `I  `** | **4 铁** |

我认为不对的地方（按严重度排）：

1. **形状不对称（几乎可判定是手滑）**：其余三档第 2 行都是**中间格**，铁钻头却把第 4 个铁放在**左格**。同样 4 个铁，只有一种摆法，视觉上像漏填；与另外三档不是同一套「模具语言」。
2. **唯独铁档没有「柄」这一层**：石/金/钻石都是「3 主材 + 1 铁（柄/夹持）」，只有铁档把柄也做成铁、4 个全是铁。用户说要加「棒/零件/中间件」，这条正是最典型的缺口 —— 修它时天然应该分化成「钻头基体 + 柄」。
3. **造价与属性倒挂**：`DrillMaterial.java:36-43` 定义铁钻头 `durability=512`（最高）、`maxMohs=7.0`（次高，仅次于钻石 10.0）、`toughness=0.50`。而金钻头 `durability=64`、`maxMohs=4.5`，造价却是 3 金 + 1 铁（金在早期比铁更稀）。**4 铁换 512 耐久，3 金 + 1 铁只换 64 耐久**，单位耐久成本差约 12 倍，金钻头几乎没有存在理由（唯一优势 speed 1.80，但 `breakChance = 0.02×(1-0.75)=0.005`，耐久只有 1/8）。
4. **用了不该用的材料**：修「铁钻头」应从「铁」的中间件出发（棒/板/基体），而不是继续堆原版铁锭 —— 否则加了中间件也接不上。

**1.2 `lead_barrel` / `lead_bucket`：名字是铅，配方收任意锭**

- `lead_barrel.json`：`"I": "geometallurgy:ingot"`，8 个任意锭 → 1 个铅桶。
- `lead_bucket.json`：同键，5 个任意锭 → 1 个铅桶。
- 证据链：26.x 的原版 `Ingredient` 看不到物品组件（`IngotCastingRecipe.java` 的类注释明确写了这一点），`geometallurgy:ingot` 是「一个物品、任意金属（含合金）」。所以「≥70% 铁」的锭也能当铅用 —— 玩家可以用 8 个铁锭造出「铅桶」。
- 为什么这是问题：铅桶的功能性卖点是**耐氢氟酸/耐酸**（`BucketMaterial.LEAD = ACID|FLUORIDE`），这是材质层级里明确的一档；用铁冒充铅等于跳过材质层级。

**1.3 容器价格倒挂：最强的陶瓷桶最便宜**

| 容器 | 配方 | 耐蚀（`BucketMaterial`） | 设计定位（代码注释） |
|--|--|--|--|
| `metal_bucket` | 5 铜锭 | 全不耐（`IRON`） | 入门桶，最便宜 |
| `glass_bucket` | 5 玻璃 | 耐酸+氧化剂 | 中档 |
| `lead_bucket` | 5 任意锭 | 耐酸+氟化物 | 高档 |
| **`ceramic_bucket`** | **4 黏土球 + 4 砖** | **四类全耐** | 注释：`CERAMIC：四类全耐，万能桶，做起来最贵` |

`BucketMaterial.java:30` 明确写「声明顺序就是从便宜到贵」，而 `ceramic_barrel` = 8 黏土球 + 1 砖、`ceramic_bucket` = 4 黏土球 + 4 砖，**最便宜的材料做出了最强的容器**。桶与桶（barrel）四档全部有同样的倒挂。

**1.4 `carbon_powder`：合成台配方是纯陷阱**

- 合成台（`carbon_powder.json`）：shapeless **2×`#minecraft:coals` → 1 碳粉**。
- 粉碎机（`CrusherBlockEntity.java:146-147`）：**1 `minecraft:charcoal` → 4 碳粉**（640 FE）。
- 代码注释（`CrusherBlockEntity.java:142-144`）自己写了「煤炭不是可再生物……1 木炭 → 4 碳粉 也比原先 2 煤炭 → 1 碳粉 的手工配方高一个量级」。
- 结论：既然已经定调机器路才是正统，这条手工配方留在桌上就是**效率差 8 倍、原料（煤）还不可再生**的陷阱。

**1.5 `mixer` 用钨棒当中心件**

- `mixer.json`：`"T": "geometallurgy:tungsten_rod"`（4 铁块 + 2 铜块 + 2 玻璃 + 1 钨棒）。
- 钨棒是**电解炉的惰性电极**（`Reagent.java:50-55`：碳棒 8 炉次 / 钨棒 64 / 钼棒 40），来源是黑钨矿（`OreMineral.WOLFRAMITE`，稀有度 S4/G3/B5，需电炉还原 144 FE/t）经电极棒配方（1 锭 + 1 棍 → 2 棒）。
- 把最贵的电解耗材放进一台基础化学机器的中心格，属**阶数错位**：搅拌器承担的 STIRRING 反应（很多基础链的必经步骤）不该被钨卡住。

### 2. 跳过中间层的配方

- **除 `lead_barrel` / `lead_bucket` / `electrode_rod`（用 `geometallurgy:ingot`）与 `mixer`（用钨棒）外，没有任何合成台配方使用本模组自己产出的材料**。全部机器/工具都拿原版方块直接拼：
  - `crusher` = 4 铁块 + 3 红石块 + 1 熔炉
  - `centrifuge` = 4 铁块 + 2 铜块 + 2 玻璃 + 1 红石块
  - `electrolysis_furnace` = 4 铜块 + 2 红石块 + 2 铁块 + 1 避雷针
  - `battery` = 5 铜锭 + 3 铁锭 + 1 红石；`wireless_sensor` = 3 铁锭 + 2 铜锭 + 1 红石
- 也就是说：**「挖矿 → 选矿 → 冶炼出金属 → 造机器」这条链在合成台上是断的**——模组自己的金属没有进入机器建造。这正对应问题 5 里「加板/棒/零件」的第一优先级。
- 钻头四档全部由原版锭直接拼（见 1.1），没有「钻头基体 / 夹头 / 柄」。
- 机器没有电路板、框架、外壳、线圈这类中间件；冶炼炉三台也没有炉体内衬/电极座。
- 现有物品集里**确实没有「板 / 棒 / 零件 / 辅助物品」这一类**：`ModItems.java` 只有手册、探测仪、4 钻头、`ingot`、`carbon_powder`、`metal_powder`、`carbon_rod`、配置器、`tungsten_rod`、`molybdenum_rod`、4 种桶。棒只有钨/钼两个特例。

### 3. 比例失调

- **碳粉**：合成 2 煤 → 1（煤不可再生）vs 粉碎 1 木炭 → 4。见 1.4。
- **容器**：见 1.3。
- **钻头耐久成本**：4 铁 → 512 耐久；3 金 + 1 铁 → 64 耐久。见 1.1。
- **mol 盐类只出不进**（表 3B）：`sodium_sulfate` 被 7 条反应产出、0 条消耗；`calcium_sulfate` 4/0；`sodium_fluoride` 4/0；`calcium_chloride` 3/0；`aluminum_chloride` 3/0；`manganese_chloride` 2/0；`sodium_sulfide` 2/0；`iron_chloride`、`zinc_chloride`、`potassium_sulfate` 各若干。这些盐一旦生成就**没有消耗路径**，只能堆在罐里 —— 是典型的「一个反应产出过多、无出路」。
- **mol 互逆对**：`2 NaOH → Na2O + H2O`（第 55 条，rate 0.05，ROASTING）与 `Na2O + H2O → 2 NaOH`（第 4 条，rate 0.8）。`MolBalance.Kind.ROASTING` 的注释（bug#36）明说这条互逆对曾在同一台反应釜里来回震荡，靠「把焙烧侧判成 ROASTING、只有还原炉收」才压住；两条并存仍是口径紧张点。
- **mol 铁的盐酸路线自相矛盾**：第 24 条硬编码 `iron_oxide + 6 HCl → 2 iron_chloride + 3 H2O`（FeCl₃），但规则侧明确禁用 `metal_acid/iron`，理由（启动日志 RULE_DISABLED）是「Fe + 稀酸生成 FeCl₂（亚铁）；表中只有 FeCl₃」。同一元素两条口径。
- **mol 右侧产物常常远多于左侧可消耗**：`water` 产出 64 次 / 消耗 12 次、`carbon_dioxide` 21/4、`sodium_sulfate` 7/0 —— 水/CO₂ 可以外排，盐不行。

- 说明：金属单质（`aluminum`/`zinc`/`manganese`/`iron`）的真正入口是**金属粉**（`MetalPowderItem` + `PowderContent`，机器把粉倒进 mol 罐），**不在这 107 条反应里**；矿物相（`iron_oxide`/`manganese_dioxide`/`silicon_dioxide`/`sulfur`）的入口是矿浆/冶炼，也不在 mol 表里。因此这两类的「只进不出」是**表外转移**，需要在文档层面补一条桥接说明；标「未确认」的是「粉/矿浆 → mol 罐」算不算配方。

**4.3 物品层孤岛（异常的那些）**

| 物品 | 消耗/产出 | 判断 |
|--|--|--|
| `geometallurgy:metal_powder` | 0 / 1 | 粉碎机产出；只经 `MetalPowderItem/PowderContent` 注入 mol 罐，**无合成消耗**。孤岛（但用途正当）。 |
| `geometallurgy:molybdenum_rod` | 0 / 1 | `electrode_rod` 产出；只作电解炉电极（耐久消耗），**无配方消耗**。与钨棒（被 mixer 消耗）不对称。 |
| `geometallurgy:tungsten_rod` | 1 / 1 | 唯一合成消费者是 `mixer`。 |
| `geometallurgy:drill_bit_*` ×4 | 0 / 每档 1 | 只在流体挖掘机里按耐久消耗，无合成下游（工具属正常）。 |
| `geometallurgy:ingot`（任意金属锭） | 6 / 0（合成台口径） | 合成台不产出它（由冶炼炉产出）；被 `lead_barrel`、`lead_bucket`、`electrode_rod`（2 条路径）、`ingot_casting`（3 个原版锭）消耗。 |
| 机器/桶/工具 | 0 / 1 | **终端产物**，无下游配方属正常，不计入孤岛。 |

### 5. 与 mol 体系的边界（建议，不实施）

**建议走 mol 账的：**

- 酸 / 碱 / 盐类中间物：目前已全部是 mol 物种，保持。
- 副产盐液的**消耗端**：`sodium_sulfate`、`calcium_sulfate`、`sodium_fluoride`、`calcium_chloride`、`aluminum_chloride`、`manganese_chloride`、`iron_chloride`、`zinc_chloride` 应补复分解/回收/建材（进玻璃、水泥、电解再生）路径，否则是死账。
- 金属单质的两套入口（物品锭/粉 vs mol 的 5 个金属物种）应统一口径：`PowderContent.speciesOf` 只认 5 种金属（`iron/copper/zinc/manganese/aluminum`，`ChemicalTags.METAL`），而 `OreMineral.valuable` 有 21 种金属产物（`chromium/tungsten/molybdenum/tin/nickel/cobalt/lead/bismuth/silver/gold/rare_earth…` 在 `ChemicalData` 里**没有对应单质物种**）。结果：冶炼能出这些金属锭，却没法把它们送进反应釜。若要「金属粉是 mol 侧唯一入口」，得补齐这 16 种金属物种，或明确它们永远只走物品线。

**建议保持物品的：**

- 电极（碳棒 / 钨棒 / 钼棒）：可堆叠、按耐久消耗的实体耗材，mol 表没有耐久概念。
- 钻头、桶/桶、机器、探测仪、手册：纯物品。
- **用户下一步要加的「板 / 棒 / 零件 / 辅助物品」建议做成物品**（可堆叠、可作配方 key），不要塞进 mol 账；mol 只保留「流体 / 溶液 / 气体 / 单质」的化学账。

**边界模糊、需要决策的：**

- `carbon_powder`：既是物品（还原剂当量 1.0、碳棒原料），又是 mol 的 `carbon` 物种来源（石墨电解）。两条线可并存，但「1 件粉 = 多少 mol」要统一（现为 `MolStock.INGOT_MOL = 0.1`）。
- 金属锭：作为物品参与 `lead_barrel` 等配方，但成分连续、原版 `Ingredient` 认不出（`IngotCastingRecipe` 注释）。**凡是要求「特定金属」的配方，都应改走 mol 载具或 `CustomRecipe`**，不要继续写 `"geometallurgy:ingot"`。
- `hypochlorous_acid` / `sulfurous_acid` / `carbonic_acid`：都是可逆的弱酸，产出后无消耗；要么给它们去处（漂白/氧化/回收），要么承认它们是中间体。

## 未能确认 / 待补

1. **矿浆 → mol 世界的转移路径**：`MetalPowderItem` 与矿浆罐之间的具体转移（算不算「配方」）未在 107 条反应/57 条路线里建模，故表 3B 中 5 个金属单质、4 个矿物相标为「只进不出」时附了表外说明，未下定论。
2. **Fe + 盐酸**：第 24 条硬编码 Fe₂O₃ + HCl → FeCl₃，规则侧禁用 Fe + 酸（理由是应生成 FeCl₂、表中只有 FeCl₃）；两者并存是有意还是遗留，未在代码里找到明确决策记录。
