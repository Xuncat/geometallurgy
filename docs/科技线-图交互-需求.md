# 科技线总图：交互与重排需求（2026-10-16，用户口径）

> 前置：等当前阶段性工作（open#2 分数份推进 → open#3 可逆 → open#1 搅拌气液 → open#4 溶解边）完工后再做。
> 现状：`manual/TechTree.java` 已改为**从超边图生成**（84 节点 / 144 边 / 15 层 / 22 回边），
> `client/TechTreeScreen.java` 支持拖动平移、滚轮缩放、悬停高亮 + 浮层、ESC 返回。

## 需求

### 1. 点击选中物质
- 现在只有**悬停**高亮（节点 + 直接上下游边）。
- 要加：**点击选中并保持**（点空白处取消）。选中态与悬停态视觉上要能区分（例如选中描边更粗/换色），
  选中后**它的直接上下游边保持高亮**，不随鼠标移开而熄灭。
- 实现落点：`TechTreeScreen` 增加 `selectedNodeId`（纯客户端状态，不存档）；
  命中测试复用现有节点矩形；绘制时把"选中集合"与"悬停集合"并集上色。

### 2. 选中后查看该物质的反应配方详情（**单独的界面**）
- 点击选中的节点再进入（例如**双击**，或选中后出现一个「查看配方」按钮 / 按 E），打开**独立界面**。
- 内容：**所有以该物质为反应物或产物的反应**，每条一行/一卡：
  \`\`\`
  2 NaCl + 2 H₂O  →  2 NaOH + 1 H₂ + 1 Cl₂
  · 类型：电解    · 机器：电解炉    · 催化剂：无    · 电极归属：Cl₂→阳极 H₂→阴极
  \`\`\`
  必填字段：反应物/产物的**名称 + 计量系数**（用现有 \`chemical.geometallurgy.*\` 键）、
  \`Kind\`（热 / 需搅拌 / 电解）、可跑的机器（\`Reaction.machines()\`）、催化剂、电极归属（\`Product.side()\`）。
  建议再标出：**当前世界是否可达**（用 \`ReactionGraph.reachableFrom\` 的结果缓存），以及缺哪种料。
- 颜色沿用总图：桥接绿 / 热蓝 / 搅拌紫 / 电解金。
- 该界面要能滚动（一个物质最多牵涉十几条反应），并且能「跳到另一端的物质」（点击产物名 → 切到它的详情）。

### 3. 图结构重排（用户：「现在的图结构也不太合理」）
- 现状分层是「DFS 断环 + 逆后序最长路径」，结果是 **15 层、22 条回边**，横向很长、回流线乱穿。
- 重排方向（建议，待实现时再定）：
  1. **按工艺阶段分列**：矿 / 选矿 / 冶炼 / 化学 / 稀土 五列（沿用手册现在已有的五个 \`stage.*\` 底色带），
     阶段内再按依赖排序 —— 算法定序、阶段由人工钉住（混合式，既不失真也不乱）；
  2. **回边画到下方弧线**，不穿节点；同层节点按"被引用次数"排序，减少交叉；
  3. 可选：**把"机器"提升为节点**（超边作为中转点），这样一眼能看出"这条线要走哪台机器"——
     代价是节点变多，做成可切换的两种视图（物质图 / 过程图）。
- 无论怎么排，节点/边**必须仍从 \`MolRecipes.all()\` + 桥接表生成**，不允许回到手写表（那正是漂移的来源）。

## 落地记录（2026-10-18，实现方）

### 1. 点击选中（client-only）—— 已完成

- `TechTreeScreen` 增 `selectedNodeId`（纯客户端、不存档）。点击在 `mouseReleased` 判定：
  拖动位移 ≤ 4px 才算点击；点节点 = 粘性选中，点空白 = 清空（按释放点重新命中测试）。
- 选中描边是 **2px 金色**、悬停是 1px 白边、正常 1px 按类型上色 —— 选中与悬停一眼可分。
- 选中的直接上下游边用金色加粗且**持续高亮**（不随鼠标移开熄灭）；悬停边白色。
  绘制只遍历一次边表，把「选中 ∪ 悬停」的边集合上亮色。

### 2. 配方详情独立界面 —— 已完成

- 新增 `client/ReactionDetailScreen.java`。进入方式：**双击**选中节点 / 选中后按 **E** /
  点右下角「查看配方」按钮；`TechTreeScreen.openRecipe()` 换屏，详情界面的 `parent` 就是总图。
- 数据来自 `TechTree.reactionsFor(id)`：化学超边（含系数、`Kind`、`machines()`、催化剂、
  `Product.side()`）**与**桥接机器步骤（矿 → 精矿 / 精矿 → 离子物种）都倒排进来。
  一条一卡，方程按 `2 NaCl + 2 H2O -> 2 NaOH + 1 H2 + 1 Cl2` 的形式写出（系数一律显示）。
- 每卡四行：**类型 / 机器 / 催化剂 / 电极归属**（可逆反应再多一行「可逆反应」）。
  颜色沿用总图：桥接绿 / 热蓝 / 搅拌紫 / 电解金。
- **可滚动**：`enableScissor` 裁剪视口，滚轮 / 上下方向键滚动，右侧滚动条。
- **点击任意物质名跳转**：方程按 token 布局，物质名记录命中矩形；点击后内部返回栈压栈、
  `speciesId` 换成目标、原地重建内容；ESC / 返回按钮逐级后退，栈空返回总图。
- **当前是否可达**：表头标「当前可达 / 当前不可达」；不可达时列出缺哪种料。
  可达集合是 `TechTree.REACHABLE`（类初始化时 `ReactionGraph.reachableFrom(ORE_ROOTS, 全机器)`
  只跑一次并缓存），详情界面**每帧只查表**，不重跑 BFS。缺料是 `TechTree.missingFor(id)`：
  列出所有能生成它的反应里、本身也不可达的反应物；一条生成路线都没有时显示「无已知生成路线」。

### 3. 图结构重排 —— 已完成

- 新增**纯类** `manual/TechTreeLayout.java`（只 import `java.util`，无 `net.minecraft`），
  把列 / 行 / 边路由 / 端点几何全搬进去：
  - **列由工艺阶段钉死**（矿 / 选矿 / 冶炼 / 化学 / 稀土 五列，复用 `stage.*` 键）；
    阶段归档在 `TechTree.stageOf(id)`：原矿 + 水 / 空气 → 0，`*_concentrate` → 1，
    `rare_earth` / `light_` / `heavy_` → 4，一张很小的「冶炼中间体」表 → 2，其余 → 3。
  - **阶段内顺序由依赖算**：Sugiyama 重心法，固定 8 轮（左→右看更左的邻居、右→左看更右的），
    平局按 id —— 确定性、环也不会挂死（不需要拓扑序）。
  - **回边（下游在更左阶段）画到整张图下方的弧线**，三条档位交错；**同列内的边**在列间
    缝里鼓侧弧。两类弧都不穿过任何节点盒；只有正向边（下游在更右的列）走直线 + 箭头。
  - 盒子不重叠是构造保证：列中心按「该列最宽节点的一半」逐列累加、列间留 `COL_GAP=120`；
    同列一行一个节点、行距 `ROW_H=30` > 节点高 18。
- `TechTree.java` 删掉了 DFS 断环 + 逆后序最长路径（及 15 层的 `layer` / `col` / `row`），
  `Node` 只留 `stage`；边 / 节点仍然**只从 `MolRecipes.all()` + `ReactionGraph` 桥接生成**，
  没有手写表。
- `TechTreeScreen` 重建时量字体宽度 → 调 `TechTreeLayout.compute` → 建盒；拖动 / 滚轮以光标
  为中心缩放 / 悬停浮层 / ESC 全部保留。

### 一次性 harness（已删除）实测

- 纯 `javac`（只编 `TechTreeLayout.java` + `LayoutHarness.java`，无任何 Minecraft 依赖）：
  `DETERMINISTIC=true`、`NO_OVERLAP=true`、`EDGE_ENDPOINTS_ON_BOUNDARY=true`、`CYCLE_TERMINATES=true`；
  含 2-环 / 3-环的图也能算完。
- 真实反应图（跑完即删的 `debug/TechTreeProbe`，经 `JavaExec` 用源码集运行）：
  **91 个节点 / 221 条投影边**，列为 **5**，每列节点数 `[17, 7, 14, 45, 8]`，
  每列行数 `[17, 7, 14, 45, 8]`（化学列最高 45 行）；路由 **正向 74 / 侧弧 101 / 下方回流弧 46**，
  相邻列交叉 **61**；整图 1304 × 1320 px。全机器可达 86 / 91。
- 计数与题面给的「15 层 + 22 回边」不可直接比：层数 = 列数（现在钉死 **5** 列），
  回边 = 下方回流弧（46 条，另有同列侧弧 101 条）。
